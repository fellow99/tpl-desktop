# 工作台 — 系统级功能规格 (Overall Specification)

> 项目: tpl-desktop（工作台）
> 文档类型: As-Built（基于源代码逆向整理）
> 最后更新: 2026-07-19

## 1. 系统目标与用户

### 1.1 系统定位

工作台是一个多页面可视化桌面应用，为个人用户提供可高度定制的信息展示与工具聚合工作区。系统运行在浏览器中，无需后端服务即可完整运作。

### 1.2 目标用户

- **个人用户**：需要在浏览器中获得一个类操作系统桌面的工作区，用于组织看板组件（Widget）、运行工具应用（App）、切换不同布局页面。

### 1.3 核心价值

- 多页面桌面空间，按场景自由切换
- 拖拽式看板布局，所见即所得
- 内置多种展示型看板组件（文本、数字、图表、媒体）
- 桌面应用叠加运行（时钟、网页工具等）
- 浅色/深色主题无缝切换
- 桌面背景个性化定制
- 登录保护与会话恢复
- 配置完全本地持久化，无需后端

## 3. 功能需求（按领域分组）

### 3.1 桌面配置管理

- **FR-SYS-001**: 系统 MUST 在启动时自动加载桌面配置，配置源为两份：静态默认配置（JSON 文件）和用户持久化配置（本地存储），用户配置覆盖默认配置。
- **FR-SYS-002**: 系统 MUST 在静态默认配置加载失败时使用内置硬编码回退配置，确保桌面始终可用。
- **FR-SYS-003**: 系统 MUST 在退出编辑模式时将完整桌面配置序列化并持久化到本地存储。
- **FR-SYS-004**: 系统 MUST 在组件卸载前（如页面关闭/刷新）保存当前桌面配置。
- **FR-SYS-005**: 桌面配置 MUST 包含以下顶级字段：主题、字号、网格参数、背景引用、页面数组、快捷方式列表。
- **FR-SYS-006**: 页面数组 MUST 至少包含一个页面，系统应在配置加载后执行兜底校验。

### 3.2 桌面视口与多页面

- **FR-SYS-007**: 系统 MUST 支持多页面桌面，通过轮播翻页组件实现页面切换（每次显示一个整页）。
- **FR-SYS-008**: 每个页面 MUST 拥有独立的网格布局实例，页面之间互不干扰。
- **FR-SYS-009**: 系统 MUST 支持页面增删：在当前页之前/之后插入新页，或删除当前页（最少保留一页）。
- **FR-SYS-010**: 页面切换时 MUST 通知即将离开的页面上的看板组件进入非活动状态，通知目标页面上的看板组件进入活动状态。
- **FR-SYS-011**: 每个网格的列数 MUST 由桌面配置的 `grid.cols` 参数控制（默认 12 列）。
- **FR-SYS-012**: 轮播翻页的分页指示器 MUST 可点击，支持直接跳转到指定页。

### 3.3 编辑器模式

- **FR-SYS-013**: 系统 MUST 支持两种桌面模式：浏览模式（normal）和编辑模式（editing），两者之间可切换。
- **FR-SYS-014**: 编辑器模式 MUST 启用看板组件的拖拽移动和大小调整，浏览模式 MUST 禁用这些交互。
- **FR-SYS-015**: 编辑器模式 MUST 禁用页面轮播的手势滑动，防止编辑拖拽时误切换页面。
- **FR-SYS-016**: 进入编辑模式时 MUST 强制显示所有看板组件的外壳标题栏（含编辑和删除按钮），退出时恢复用户的外框显示设置。
- **FR-SYS-017**: 系统 MUST 在模式切换时向所有看板组件广播模式变更事件。

### 3.4 看板组件（Widget）管理

- **FR-SYS-018**: 系统 MUST 支持从组件列表中选择看板组件并添加到当前页面的网格中。新组件默认放置在页面底部。
- **FR-SYS-019**: 系统 MUST 支持通过鼠标拖放（HTML5 Drag and Drop）将组件列表中的条目拖入网格放置。
- **FR-SYS-020**: 看板组件 MUST 在网格中可拖拽移动和调整大小（仅在编辑模式下）。
- **FR-SYS-021**: 看板组件的初始属性值 MUST 从其元数据声明中获取默认值。
- **FR-SYS-022**: 新添加的看板组件的唯一标识符 MUST 在创建时生成（基于时间戳）。
- **FR-SYS-023**: 系统 MUST 支持删除看板组件（从网格中移除）。
- **FR-SYS-024**: 已注册但 Vue 组件文件缺失的看板组件，系统 MUST 渲染「组件未找到」的占位文本，不中断运行。
- **FR-SYS-025**: 新的看板组件只需在对应目录下添加源文件对（组件 Vue 文件 + 元数据 JS 文件），系统 MUST 在构建时自动发现并注册，无需手动修改注册入口代码。

### 3.5 App 应用系统

- **FR-SYS-026**: 系统 MUST 支持打开 App 应用，App 以全屏叠加层形式渲染在桌面视口之上。
- **FR-SYS-027**: 每个 App 实例 MUST 拥有标题栏（含最小化和关闭按钮），通过外壳组件包裹。
- **FR-SYS-028**: 打开中的 App MUST 可最小化（CSS 隐藏但实例保持存活）和恢复、可关闭（销毁实例）。
- **FR-SYS-029**: 同一 App（按 compName 或 compId 识别）重复打开时 MUST 不创建新实例，而是恢复已有实例并置于顶层。
- **FR-SYS-030**: 当有 App 处于打开状态时，系统 MUST 通知当前页所有看板组件进入非活动状态（以便看板组件暂停动画或交互）；当所有 App 关闭后，MUST 通知看板组件恢复活动。
- **FR-SYS-031**: App 状态变更通知 MUST 有防抖处理（约 300ms），避免快速打开/关闭导致事件序列混乱。

### 3.6 桌面背景系统

- **FR-SYS-032**: 系统 MUST 支持从背景选择面板中选取桌面背景，选中的背景在全视口之下渲染。
- **FR-SYS-033**: 系统 SHOULD 支持两种背景类型：静态图片（image）和动态视频（video），由背景元数据的 `type` 字段指定。
- **FR-SYS-034**: 选择背景时，如果该背景声明了主题偏好，系统 MUST 自动切换到对应主题（浅色/深色）。
- **FR-SYS-035**: 背景选择面板 MUST 支持按分类筛选（如暗色系、浅色系、动态）。
- **FR-SYS-036**: 新的背景只需在对应目录下添加元数据文件，系统 MUST 在构建时自动发现并注册。

### 3.7 主题系统

- **FR-SYS-037**: 系统 MUST 支持浅色主题和深色主题的切换。
- **FR-SYS-038**: 主题切换 MUST 即时生效，无需刷新页面。
- **FR-SYS-039**: 用户的主题偏好 MUST 持久化到本地存储，下次访问时自动恢复。
- **FR-SYS-040**: 系统 MUST 在 HTML 页面加载之初（Vue 挂载前）执行反闪烁脚本，根据已保存的主题预先设置样式，避免主题闪烁。
- **FR-SYS-041**: 当用户从未手动设置过主题时，系统 SHOULD 自动跟随操作系统的浅色/深色偏好；一旦用户手动设置，则以用户设置为准。

### 3.8 认证系统

- **FR-SYS-042**: 系统 MUST 在用户访问桌面功能前要求登录。
- **FR-SYS-043**: 登录时密码 MUST 使用非对称加密（RSA 公钥加密）后传输，公钥由运行时配置注入。
- **FR-SYS-044**: 系统 MAY 在认证后端不可达时降级到本地模拟用户数据校验（仅开发环境）。模拟校验的密码比对 MUST 仅发生在本地，不传输。
- **FR-SYS-045**: 登录成功后用户信息 MUST 缓存到本地存储，敏感字段（如密码）MUST 不被持久化。
- **FR-SYS-046**: 系统 MUST 支持会话恢复：启动时检查缓存的登录信息，有效则自动恢复会话，无效或不存在则显示登录界面。
- **FR-SYS-047**: 退出登录时 MUST 清除缓存的登录信息与会话数据，然后刷新页面。

### 3.9 属性编辑

- **FR-SYS-048**: 系统 MUST 支持通过属性编辑面板修改看板组件的属性值和外框属性。
- **FR-SYS-049**: 属性编辑面板 MUST 支持「取消」操作（丢弃修改，不影响组件当前值）和「应用」操作（提交修改并更新组件）。
- **FR-SYS-050**: 属性编辑表单 MUST 根据属性元数据的类型声明动态渲染对应的编辑器控件（文本输入、数值输入、开关、代码编辑器、Markdown 编辑器等）。
- **FR-SYS-051**: 属性编辑确认后 MUST 立即重渲染对应组件并持久化到本地存储。

### 3.10 快捷方式管理

- **FR-SYS-052**: 用户 MAY 将已注册的 App 固定为快捷方式，显示在底部主工具条上。
- **FR-SYS-053**: 已固定的快捷方式 MUST 随桌面配置一起持久化。
- **FR-SYS-054**: 移除已固定的快捷方式 MUST 不删除 App 本身。

### 3.11 字体缩放

- **FR-SYS-055**: 系统 MUST 支持全局字号调整（+2px / -2px / 还原为 16px）。
- **FR-SYS-056**: 字号 MUST 不低于 10px。

## 4. 非功能需求

### 4.1 性能

- **NFR-PERF-001**: 页面切换延迟 SHOULD 控制在 300ms 以内（Swiper speed=300）。
- **NFR-PERF-002**: 看板组件在非活动状态时 SHOULD 暂停动画和定时器以节省资源。
- **NFR-PERF-003**: App 打开/关闭事件通知 SHOULD 有 300ms 防抖，避免高频状态抖动。

### 4.2 持久化

- **NFR-PERS-001**: 桌面配置 MUST 在退出编辑模式、组件卸载前、属性编辑确认后三个时机持久化。
- **NFR-PERS-002**: 本地存储不可用时（隐私模式、存储禁用），系统 MUST 静默降级，不抛出错误阻断正常使用。
- **NFR-PERS-003**: 序列化失败的旧数据 MUST 被静默丢弃并回退到默认配置。

### 4.3 可扩展性

- **NFR-EXT-001**: 新增看板组件、App 应用、桌面背景 MUST 仅需添加对应目录下的源文件对，无需修改任何注册入口代码（构建时自动扫描）。
- **NFR-EXT-002**: 元数据文件缺失时系统 MUST 自动补充最小默认元数据，不中断注册流程。
- **NFR-EXT-003**: 属性编辑器类型系统 SHOULD 支持扩展新类型（通过 type 字段 + 新增分支或自定义组件）。

### 4.4 浏览器兼容性

- **NFR-BROWSER-001**: 系统 MUST 支持现代浏览器（Chrome、Firefox、Edge、Safari 的最新两个主要版本）。
- **NFR-BROWSER-002**: 系统 SHOULD 支持本地存储 API 和 CSS 变量（--desktop-* 体系）。

## 5. 系统边界

### 5.1 明确排除

| 排除项 | 说明 |
|--------|------|
| 后端服务 | 工作台是纯前端应用，不依赖任何后端服务。所有数据基于本地存储持久化。认证有模拟降级路径但不包含真实后端认证逻辑。 |
| 多用户协同 | 不支持多用户同时编辑同一桌面，每个用户独立使用自己的本地存储。 |
| 页面路由 | 不使用 vue-router 或任何前端路由库，整个应用为单一 HTML 入口的单页面应用。 |
| SDK/插件市场 | 当前不支持第三方开发 SDK 或在线安装插件。新增组件通过源代码目录添加文件实现。 |
| 国际化 (i18n) | 当前界面文字为硬编码中文，无多语言框架或翻译机制。 |
| 自动化测试 | 当前代码库不包含任何自动化测试（单元测试、组件测试、E2E 测试）。 |
| TypeScript | 当前代码库为纯 JavaScript，不包含 TypeScript 类型定义。 |
| 事件总线 | 不使用 mitt 或任何第三方事件总线库。事件通信通过 Vue props/emits + useGridStack 内部事件桥接实现。 |
| 集中式状态管理 | 不使用 Pinia 或任何集中式状态管理库。状态管理通过 Vue ref() + composable 模块级单例实现。 |

### 5.2 系统依赖

| 外部依赖 | 用途 | 降级策略 |
|----------|------|----------|
| 运行时配置文件 `config.js` | 注入认证 URL 与 RSA 公钥 | 部署后可直接编辑，无需重新构建 |
| 默认桌面配置 JSON 文件 `DEFAULT_DESKTOP_JSON.json` | 首次加载的基础布局 | fetch 失败 → 硬编码回退配置 |
| 模拟用户数据 JSON 文件 `USERS_MOCK.json` | 开发环境认证降级 | 仅后端不可达时使用；后端可用则走 RSA 加密路径 |
