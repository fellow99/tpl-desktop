## TC-101-001: 打开属性编辑面板

- **前置条件**:
  - 用户已登录，桌面处于编辑模式（`desktopMode === 'editing'`）
  - 桌面上存在一个「基础文字」Widget（compName=`BasicText`），标题栏可见
- **步骤**:
  1. 点击「基础文字」Widget 标题栏的「编辑」按钮（笔形图标）
- **预期结果**:
  - 右侧滑入一个 380px 宽的抽屉面板（`el-drawer`），标题显示「属性编辑」
  - 面板默认激活「组件属性」标签页
  - 「组件属性」标签页下显示一个「文本内容」输入框，值为 "这是一段文字"（来自 BasicText 元数据默认值）
  - 底部显示「取消」和「应用」两个按钮，「应用」按钮为 primary 样式且未禁用
- **关联 FR**: FR-101-001, FR-101-002, FR-101-006
- **优先级**: P0

## TC-101-002: 修改文本属性并保存

- **前置条件**:
  - 属性编辑面板已打开，「基础文字」Widget 的「文本内容」输入框显示 "这是一段文字"
- **步骤**:
  1. 将「文本内容」输入框的值修改为 "Hello World"
  2. 点击「应用」按钮
- **预期结果**:
  - 属性编辑面板关闭（抽屉滑出）
  - Widget 内容区域立即显示 "Hello World"
  - 刷新页面后 Widget 仍显示 "Hello World"（持久化生效）
- **关联 FR**: FR-101-015, FR-101-022
- **优先级**: P0

## TC-101-003: 修改数字属性并保存

- **前置条件**:
  - 桌面上有一个「滚动数字」Widget（compName=`BasicNumber`）
  - 属性编辑面板已打开，默认激活「组件属性」标签页
- **步骤**:
  1. 确认「数值」字段显示 `123.456`（来自 BasicNumber 元数据默认值）
  2. 将「数值」修改为 `999.99`
  3. 将「小数保留位数」修改为 `3`
  4. 将「标题文字」修改为 "我的数字"
  5. 将「单位文字」修改为 "元"
  6. 点击「应用」
- **预期结果**:
  - 面板关闭
  - Widget 显示数值 999.99，精度 3 位小数，标题 "我的数字"，单位 "元"
  - 刷新后持久化生效
- **关联 FR**: FR-101-015, FR-101-017
- **优先级**: P0

## TC-101-004: 数字输入非法值回退

- **前置条件**:
  - 属性编辑面板已打开，编辑「滚动数字」Widget，「数值」字段当前值为 `123.456`
- **步骤**:
  1. 清空「数值」字段内容（设为空字符串）
  2. 点击页面其他区域使输入框失去焦点（触发 change 事件）

  - 「数值」字段自动回退为 `123.456`（`propMeta.default`）
- **备选步骤**:
  3. 将「数值」输入 `abc`（非数字文本）
  4. 失去焦点
- **备选预期结果**:
  - 「数值」字段自动回退为默认值 `123.456`
- **关联 FR**: FR-101-017, FR-101-018
- **优先级**: P1

## TC-101-011: JSON 属性格式校验 — 合法输入

- **前置条件**:
  - 存在一个 Widget，其 `meta.props` 中某个属性声明 `type: 'json'`（当前基础 Widget 中无此类型，需构造测试场景或未来扩展 Widget 验证）
- **步骤**:
  1. 打开该 Widget 的属性编辑面板
  2. 在 JSON 编辑区域（等宽字体 textarea）输入合法的 JSON 字符串：`{"key": "value", "num": 123}`
  3. 点击编辑区域外部使其失去焦点
- **预期结果**:
  - 输入框无红色边框
  - 无错误提示
  - 点击「应用」后 Widget 正常接收该 JSON 值
- **关联 FR**: FR-101-019
- **优先级**: P1

---

## TC-101-012: JSON 属性格式校验 — 非法输入

- **前置条件**:
  - 同 TC-101-011
- **步骤**:
  1. 在 JSON 编辑区域输入非法 JSON 字符串：`{key: value}`（缺少引号）
  2. 点击编辑区域外部使其失去焦点
- **预期结果**:
  - 输入框显示红色边框（`.is-error` class）
  - 输入框下方显示红色文字「JSON 格式错误」
  - 弹出 `ElMessage.error` 通知：「属性「{title}」JSON 格式错误」
  - 用户输入的内容**保留**在输入框中（未被清除）
  - 用户可以继续编辑修正格式
- **步骤（继续）**:
  3. 将内容修正为合法 JSON：`{"key": "value"}`
  4. 再次失去焦点
- **预期结果（继续）**:
  - 红色边框消失
  - 错误提示文字消失
- **步骤（继续）**:
  5. 清空输入框内容（空字符串）
  6. 失去焦点
- **预期结果（继续）**:
  - 无错误提示（空值通过校验）
- **关联 FR**: FR-101-020
- **优先级**: P1

## TC-101-013: 切换编辑目标（不同 Widget）属性不混淆

- **前置条件**:
  - 桌面上有 Widget A（「基础文字」，文本内容 = "AAA"）和 Widget B（「基础文字」，文本内容 = "BBB"）
- **步骤**:
  1. 点击 Widget A 的「编辑」按钮，面板打开，文本内容 = "AAA"
  2. 将文本内容修改为 "AAA Modified"（**不**点击「应用」）
  3. **不关闭面板**，直接点击 Widget B 的「编辑」按钮
- **预期结果**:
  - 面板内容刷新为 Widget B 的属性值
  - 「文本内容」字段显示 "BBB"（**不是** "AAA Modified"）
  - Widget A 的内容仍显示 "AAA"（编辑副本被丢弃）
- **步骤（继续）**:
  4. 将 Widget B 的文本内容修改为 "BBB Modified"
  5. 点击「应用」
- **预期结果（继续）**:
  - Widget B 显示 "BBB Modified"
  - Widget A 仍显示 "AAA"
- **关联 FR**: FR-101-002
- **优先级**: P0

## TC-101-017: 下拉选项属性编辑（select 类型回退文本输入）

- **前置条件**:
  - 桌面上有一个「基础图片」Widget（compName=`BasicImage`，含 `objectFit` 属性，type=`'select'`，options 5 个选项）
  - 属性编辑面板已打开，切换到「组件属性」标签页
- **步骤**:
  1. 确认「适应方式」字段渲染为普通文本输入框（`el-input type=text`），**不是**下拉选择器（因为 select 编辑器未实现）
  2. 输入框当前值为 `"cover"`（来自 BasicImage 元数据默认值）
  3. 手动将值修改为 `"contain"`
  4. 点击「应用」
- **预期结果**:
  - Widget 图片的适应方式变为 `contain`（CSS `object-fit: contain`）
- **关联 FR**: FR-101-013, FR-101-015
- **优先级**: P2
