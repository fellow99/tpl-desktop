# 桌面框架（Desktop Framework）规格文档

> 模块: 001-desktop-framework
> 状态: 已实现
> 最后更新: 2026-07-19

## 1. 模块概述

### 1.1 目的 — 为什么存在此模块

桌面框架模块是工作台的**核心编排层**，负责多页面桌面的全部结构骨架：页面导航、网格布局引擎、编辑/浏览双模式切换、工具栏与状态栏 chrome，以及桌面配置的加载、合并与持久化。它是整个应用的"脊椎"——所有其他模块（小部件、App、背景、主题、属性编辑）均通过此模块进行编排与协调。

### 1.2 解决的问题

- 需要一个支持多页面、手势滑动、页码指示器的桌面容器框架
- 每页需要独立的可拖拽网格布局，多实例需统一管理生命周期
- 浏览模式与编辑模式之间需要无缝切换，编辑时保护布局不被意外手势破坏
- 桌面配置需要在默认模板与用户保存之间双向合并，支持刷新后恢复
- 需要一个统一的 orchestration 入口协调所有子模块（小部件面板、背景面板、主题、字体、App 等）的显隐与数据流
- 底部工具栏需要按模式显示不同操作集合（主页、快捷方式 vs 背景、部件、页面、主题、字号）
- 顶部状态栏需要实时时钟和模式切换入口

### 1.3 范围

**包含**：
- 多页面桌面容器与页面切换（手势滑动 + 页码指示器 + 点击跳转）
- 每页独立的可拖拽网格布局引擎（初始化、销毁、活动/非活动状态切换）
- 编辑模式与浏览模式的全局切换，以及两种模式下网格交互性和页面滑动手势的差异化行为
- 网格节点事件向内部组件的桥接通信机制
- 桌面配置的双源加载（默认模板 + 用户存储）与合并持久化
- 页面增删管理（前插、后插、移除，最少保留一页）
- 全局字体缩放（加大、减小、还原）
- 底部工具栏（浏览模式：主页/App 列表/快捷方式/运行中应用；编辑模式：背景/部件/主题/页面/字号/完成）
- 顶部状态栏（实时时钟 + 编辑入口 + 用户信息与登出）
- 主页按钮（回首页 + 最小化所有 App）
- HTML5 拖放放置（将外部元素拖入指定网格位置）
- 网格布局数据的序列化与反序列化

**不包含**：
- 小部件组件的具体实现与元数据注册（属于 002-widget-system）
- 小部件外壳容器（desktop-widget-wrapper）的内部实现（属于 002-widget-system）
- App 叠加层的渲染、App 组件内部实现（属于 003-app-system）
- App 列表与 App 市场的具体组件（属于 003-app-system）
- 背景渲染层的具体实现、背景元数据注册（属于 004-background-system）
- 主题引擎（CSS 变量定义、html.dark 切换逻辑，属于 005-theme-system）——但主题切换按钮的编排和配置持久化属于本模块
- 属性编辑面板的具体组件（属于 101-prop-editor，但打开面板的编排属于本模块）
- 登录认证的业务逻辑与 auth-service（属于模块 201-page-index 管理的外部服务）
- 应用入口 bootstrap（src/desktop.js，属于模块 201-page-index）

## 2. 用户故事

- US-001: 作为用户，我可以在多页面桌面之间手势滑动切换，每页拥有独立的网格布局。
- US-002: 作为用户，我可以通过底部页码指示器查看当前页码并点击跳转到指定页。
- US-003: 作为用户，在浏览模式下网格节点不可拖拽、不可调整大小，仅展示内容。
- US-004: 作为用户，在编辑模式下网格节点可拖拽移动、可调整大小，页面不可手势滑动以免冲突。
- US-005: 作为用户，我可以在编辑模式下添加新页面（在当前页之前或之后），并删除不需要的页面（至少保留一页）。
- US-006: 作为用户，退出编辑模式时桌面布局会自动保存，刷新后布局保持不变。
- US-007: 作为用户，首次使用时会加载默认桌面配置，我的自定义配置会覆盖默认值并持久化。
- US-008: 作为用户，我可以通过底部工具栏快速操作：主页、App 列表、快捷方式、运行中应用。
- US-009: 作为用户，在编辑模式下工具栏切换为编辑工具集：更换背景、添加部件、切换主题、管理页面、调整字号、完成编辑。
- US-010: 作为用户，我可以调整桌面整体字号（加大/减小/还原），设置会持久化保存。
- US-011: 作为编辑者，我可以在编辑模式下将部件拖放到网格中的指定位置。
- US-012: 作为用户，切换页面时旧页部件暂停交互、新页恢复活跃。

## 3. 功能需求

### 3.1 配置加载与持久化

- FR-001-001: 系统 MUST 从双源加载桌面配置：先获取默认配置模板，再与用户本地存储的配置合并（用户配置优先覆盖默认值）。
- FR-001-002: 当默认配置模板获取失败时，系统 MUST 回退到内置硬编码配置（含单页空桌面、浅色主题、16px 字号、12×8 网格）。
- FR-001-003: 当用户本地存储解析失败时，系统 MUST 静默回退到仅使用默认配置。
- FR-001-004: 系统 MUST 保证 pages 数组始终非空（至少包含一个页面），作为防御性兜底。
- FR-001-005: 系统 MUST 在退出编辑模式时自动持久化完整桌面配置到本地存储。
- FR-001-006: 系统 MUST 在组件卸载前（如页面关闭/刷新）尝试保存桌面配置。
- FR-001-007: 本地存储操作 MUST 被 try/catch 包裹，失败时静默降级不阻断用户操作。

### 3.2 桌面模式

- FR-001-008: 系统 MUST 支持两种桌面模式：常规浏览模式（normal）和编辑模式（editing）。
- FR-001-009: 切换进入编辑模式 MUST 可通过状态栏编辑图标触发。
- FR-001-010: 切换退出编辑模式 MUST 可通过状态栏或编辑工具条的"完成"按钮触发。
- FR-001-011: 退出编辑模式时 MUST 依次执行：隐藏所有弹出面板、序列化所有页面布局、持久化配置。
- FR-001-012: 编辑模式下 MUST 自动禁用页面手势滑动，浏览模式下启用。
- FR-001-013: 编辑模式下所有页面的网格节点 MUST 可拖拽移动和调整大小；浏览模式下 MUST 禁止拖拽和调整大小。
- FR-001-014: 模式切换时 MUST 向所有已存在的网格内节点广播模式变更事件，并重渲染所有节点以更新交互外观。

### 3.3 页面管理

- FR-001-015: 系统 MUST 支持在当前页之前插入一页空页面，并自动切换到新页。
- FR-001-016: 系统 MUST 支持在当前页之后插入一页空页面，并自动切换到新页。
- FR-001-017: 插入新页前 MUST 先将现有页面布局序列化（避免未保存变更丢失）。
- FR-001-018: 系统 MUST 支持移除当前页面，但至少保留一页——当仅有一页时移除操作不可用。
- FR-001-019: 移除页面后若当前索引越界，MUST 自动调整到最后一页。
- FR-001-020: 页面增删操作 MUST 在修改页面结构后立即持久化配置。

### 3.4 多页面导航与网格布局

- FR-001-021: 系统 MUST 提供多页面容器，每页独占视口、通过手势滑动或页码指示器点击切换。
- FR-001-022: 每页 MUST 拥有独立的网格布局引擎实例，实例间互不干扰。
- FR-001-023: 网格引擎初始化 MUST 从配置数据加载网格参数（列数）和已有节点布局。
- FR-001-024: 系统 MUST 在视口组件卸载时销毁所有网格实例并清理相关事件注册。
- FR-001-025: 首页在初始化完成后 MUST 自动激活（其网格节点进入活跃交互状态）。
- FR-001-026: 页面切换时 MUST 先停用旧页（其网格节点退出交互状态），再激活新页。
- FR-001-027: 活动状态无变化时 MUST 跳过重复的状态广播。
- FR-001-028: 网格节点在页面上的挂载 MUST 在运行时动态完成（添加、移除、切换模式），不支持通过静态模板渲染。

### 3.5 网格数据序列化

- FR-001-029: 系统 MUST 支持将单个页面的网格布局序列化回配置数据（节点坐标、尺寸、组件名、属性值、外壳值）。
- FR-001-030: 系统 MUST 支持一次性序列化所有页面的网格布局。
- FR-001-031: 序列化时 MUST 从活跃引擎节点显式回填自定义字段（组件信息、属性值、外壳值），不依赖引擎内部克隆行为。

### 3.6 网格事件桥接

- FR-001-032: 系统 MUST 在网格节点被添加、移除、拖拽开始/结束、调整大小开始/结束时，向对应内部组件实例发送事件通知。
- FR-001-033: 发送的事件载荷 MUST 包含节点标识和位置/尺寸信息。
- FR-001-034: 节点移除时 MUST 注销其事件桥接，防止内存泄漏。

### 3.7 HTML5 拖放放置

- FR-001-035: 编辑模式下视口 MUST 接收外部拖放事件，并根据鼠标落点计算目标网格坐标。
- FR-001-036: 非编辑模式下 MUST 阻止外部拖放。
- FR-001-037: 拖放数据 MUST 以 JSON 格式传输，包含组件标识和可选参数。

### 3.8 主页按钮

- FR-001-038: 主页按钮 MUST 跳转到首页（第 0 页）并将所有已打开的 App 最小化（不关闭）。

### 3.9 字体缩放

- FR-001-039: 系统 MUST 支持字体加大：每次增加 2px，无上限。
- FR-001-040: 系统 MUST 支持字体减小：每次减少 2px，最小 10px。
- FR-001-041: 系统 MUST 支持字体还原：恢复至 16px。
- FR-001-042: 字体变更 MUST 立即应用到桌面根元素并持久化。
- FR-001-043: 字体默认值 MUST 为 16px。

### 3.10 工具栏

- FR-001-044: 浏览模式下 MUST 渲染主工具栏（底部固定、常态下沉仅露出边缘、悬停滑出），包含：主页按钮、App 列表入口、快捷方式列表、运行中 App 列表。
- FR-001-045: 编辑模式下 MUST 渲染编辑工具栏（底部固定、完全可见），包含：背景入口、部件入口、主题切换、页面管理下拉菜单（前加/后加/移除）、字号调整下拉菜单（加大/减小/还原）、完成编辑按钮。
- FR-001-046: 页面管理下拉中的"移除本页"选项当且仅当总页数大于 1 时可用。
- FR-001-047: 工具栏 MUST 仅通过事件向上报告操作意图，不直接修改状态。

### 3.11 状态栏

- FR-001-048: 状态栏 MUST 显示实时时钟（HH:MM:SS + 年月日 + 星期），每秒刷新。
- FR-001-049: 时钟区域 MUST 不拦截用户对桌面背景的交互事件。
- FR-001-050: 状态栏 MUST 提供桌面模式切换入口（编辑图标进入编辑模式、完成图标退出编辑模式）。
- FR-001-051: 状态栏 MUST 显示当前登录用户信息，并提供用户详情弹窗与退出登录按钮。

### 3.12 主题切换编排

- FR-001-052: 系统 MUST 在编辑工具栏提供主题切换入口，切换后立即更新配置中的主题字段并持久化。
- FR-001-053: 系统 MUST 在页面加载时自动应用配置中保存的主题。

## 4. 关键实体

| 实体 | 描述 | 关键属性 |
|---|---|---|
| DesktopConfig | 完整桌面配置对象 | theme, font-size, grid { cols, rows }, background, pages[], shortcuts[] |
| Page | 单个桌面页面 | title, children[] (网格节点数组) |
| GridNode | 网格布局中的一个节点 | id, x, y, w, h, noResize, info { compName, presetKey? }, propsValues, wrapperValues |
| DesktopMode | 桌面运行模式 | 'normal'（浏览）/ 'editing'（编辑） |
| GridInstance | 单个页面的网格布局引擎实例 | key（page_N）, 关联的容器元素, 节点列表 |
| WidgetEventBridge | 网格节点 ID 到内部组件事件发射器的映射 | nodeId → emit 函数 |
| PageState | 页面激活状态 | active（网格节点可交互）/ inactive（网格节点暂停交互） |
| Shortcut | 快捷方式定义 | compName, appMeta, compId? |
| FontSize | 桌面根字体大小 | 字符串值如 '16px'，最小 10px，步长 2px |
| ToolbarMain | 浏览模式底部工具条 | 主页、App 列表、快捷方式、运行中 App |
| ToolbarEdit | 编辑模式底部工具条 | 背景、部件、主题、页面、字号、完成 |

## 5. 验收场景

### 场景 5.1：首次加载默认配置

- Given 用户首次访问且本地无保存数据
- When 桌面加载完成
- Then 显示单页空桌面（12 列网格）、浅色主题、16px 字号，工具栏和状态栏正常渲染

### 场景 5.2：配置持久化与恢复

- Given 用户已登录，在编辑模式下添加了部件并调整了布局
- When 用户点击"完成"退出编辑模式，刷新页面
- Then 桌面恢复之前保存的布局、部件位置、主题和字号设置

### 场景 5.3：默认配置加载失败

- Given 网络不可达，默认配置 JSON 获取失败
- When 桌面加载
- Then 使用内置硬编码配置正常渲染（单页空桌面、浅色主题），不显示错误

### 场景 5.4：多页面切换

- Given 桌面有 3 个页面，当前在第 1 页
- When 用户左滑到第 2 页（或点击页码指示器第 3 个点）
- Then 第 1 页网格节点暂停交互，第 2 页网格节点恢复活跃，底部指示器同步更新

### 场景 5.5：进入编辑模式

- Given 桌面处于浏览模式，有 2 个页面
- When 用户点击状态栏编辑图标
- Then 页面手势滑动被禁用、所有页面的网格节点可拖拽和调整大小、底部工具栏切换为编辑工具条

### 场景 5.6：退出编辑模式并保存

- Given 桌面处于编辑模式，用户移动了部件的网格位置
- When 用户点击"完成"按钮
- Then 布局变更被序列化保存到本地存储、切换回浏览模式、网格节点不可拖拽、底部工具栏显示为主工具条

### 场景 5.7：在当前页之前添加页面

- Given 桌面有 2 页，当前在第 1 页
- When 用户通过编辑工具条"页面 → 往前添加"
- Then 在第 1 页之前插入新空页，自动切换到新页（新页成为第 1 页），原第 1 页变为第 2 页

### 场景 5.8：移除当前页（多于 1 页时）

- Given 桌面有 3 页，当前在第 2 页
- When 用户通过编辑工具条"页面 → 移除本页"
- Then 第 2 页被移除，自动显示第 2 页（原第 3 页），"移除本页"仍然可用

### 场景 5.9：仅剩一页时不可移除

- Given 桌面仅有 1 页
- When 用户打开编辑工具条"页面"下拉菜单
- Then "移除本页"选项为禁用状态

### 场景 5.10：字体缩放

- Given 桌面字号为 16px
- When 用户依次点击"加大"→"加大"→"减小"→"还原"
- Then 字号依次变为 18px → 20px → 18px → 16px，桌面文字大小实时变化

### 场景 5.11：HTML5 拖放放置部件

- Given 桌面处于编辑模式，在外部的部件列表拖拽了一个部件
- When 用户将部件拖入视口的网格位置 (x:3, y:2)
- Then 在对应网格坐标创建一个新节点并渲染对应部件

### 场景 5.12：主页按钮

- Given 桌面有 3 页，当前在第 3 页，有 2 个 App 处于打开状态
- When 用户点击主工具栏"主页"按钮
- Then 跳转到第 1 页，所有 App 最小化（不关闭）

### 场景 5.13：状态栏时钟

- Given 桌面已加载
- When 观察状态栏左侧
- Then 显示当前时间（HH:MM:SS 格式）和日期（YYYY 年 MM 月 DD 日 周 X），每秒刷新

### 场景 5.14：用户信息与登出

- Given 用户已登录
- When 点击状态栏用户按钮，在弹窗中点击"退出登录"
- Then 清除本地存储的桌面配置，刷新页面

### 场景 5.15：主工具栏悬浮显示

- Given 桌面处于浏览模式
- When 鼠标悬停在屏幕底部
- Then 主工具栏完全滑出显示

### 场景 5.16：浏览模式快捷方式打开 App

- Given 主工具栏有已添加的快捷方式
- When 用户点击某个快捷方式
- Then 该 App 在桌面上打开（若已打开则恢复并置顶）

## 6. 非功能需求

- NFR-001: 页面切换 MUST 为 O(1) 操作（仅更新活动状态索引，不重建页面）
- NFR-002: 网格实例创建和销毁 MUST 正确清理 DOM 节点和 Vue 组件实例，无内存泄漏
- NFR-003: 配置持久化 MUST 在退出编辑模式时同步完成，不依赖异步回调
- NFR-004: 状态栏时钟更新 SHOULD 使用等宽数字，避免秒数跳动时文字抖动
- NFR-005: 所有本地存储操作 SHOULD 包括静默降级处理（隐私模式/存储满时不中断应用）
- NFR-006: 页面增删后网格实例的重建 MUST 在单次 nextTick 内完成，避免视觉闪烁

## 7. 假设与约束

- 桌面配置采用浅合并策略：用户本地存储覆盖默认配置的顶层键值，不进行深度合并
- 网格节点标识使用时间戳字符串生成，在正常用户操作速度下可接受冲突概率
- 页面数量可动态增减，每页独立管理其网格实例
- 默认网格配置全局禁用 resize（disableResize: true），编辑模式下方可调整大小
- 默认配置 JSON 位于应用 public 目录下，通过 HTTP fetch 加载
- [NEEDS CLARIFICATION] 字体加大操作无上限——超大字号是否需要在产品层面设定合理上限（如 32px）？
- [NEEDS CLARIFICATION] 本地存储键名 'dashboard-desktop-data' 为单用户设计——多用户场景下是否需要按 userId 隔离？
- [NEEDS CLARIFICATION] 编辑模式下是否允许删除有子节点的非空页面——当前实现允许直接删除，页面上的部件将丢失。

## 8. 依赖关系

### 上游依赖（本模块调用/消费）

| 模块 | 依赖类型 | 说明 |

| 004-background-system | 编排 | 处理背景选择事件、更新 desktopConfig.background |

| 101-prop-editor | 编排 | 编排属性编辑面板的打开/关闭和 confirm 事件分发 |
| 201-page-index | 消费 | 由 201 的 bootstrap 挂载；消费 loginUser、restoreSession 等认证相关状态 |
