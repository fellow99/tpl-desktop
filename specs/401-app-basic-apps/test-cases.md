## BasicClock — 时钟

### TC-401-001: 启动 BasicClock 并验证时钟显示

| 项目 | 内容 |
|------|------|
| **前置条件** | 用户已登录桌面；"时钟"已从 App 市场添加到 App 列表；当前无运行 App |
| **步骤** | 1. 点击底部工具条「⊞ App」打开 App 列表；2. 在列表中找到"时钟"条目并点击启动 |
| **预期结果** | ① 全屏叠加层中渲染时钟组件；② 显示当前时间（格式为 HH:mm:ss，如"14:30:25"）；③ 日期行显示"YYYY年MM月DD日 周X"；④ 每秒钟时间数字更新（观察到秒位进位）；⑤ 数字字体为等宽（tabular-nums），数字变化时无水平抖动 |
| **关联 FR** | FR-401-001, FR-401-004, FR-401-006 |
| **优先级** | P0 |

### TC-401-002: 切换 BasicClock 时间格式

| 项目 | 内容 |
|------|------|
| **前置条件** | BasicClock 正在运行（TC-401-001 通过） |
| **步骤** | 1. 通过 App 属性编辑器将 `format` 属性值改为 `'hh:mm:ss A'`（12 小时制 + AM/PM）；2. 确认变更 |
| **预期结果** | ① 时钟显示切换为 12 小时制（如"02:30:25 PM"）；② 时间仍每秒更新 |
| **关联 FR** | FR-401-002 |
| **优先级** | P1 |

### TC-401-003: 隐藏 BasicClock 日期行

| 项目 | 内容 |
|------|------|
| **前置条件** | BasicClock 正在运行，当前显示时间 + 日期两行 |
| **步骤** | 1. 通过 App 属性编辑器将 `showDate` 设为 `false`；2. 确认变更 |
| **预期结果** | ① 日期行从界面消失（DOM 移除，非 CSS 隐藏）；② 时间行仍然显示并更新；③ 时间行居中对齐不受影响 |
| **关联 FR** | FR-401-003, FR-401-004 |
| **优先级** | P1 |

## BasicIframe — 网页应用

### TC-401-004: 启动 BasicIframe 并验证外部页面加载

| 项目 | 内容 |
|------|------|
| **前置条件** | 用户已登录桌面；"网页应用"已从 App 市场添加到 App 列表；网络连接正常 |
| **步骤** | 1. 点击工具条「⊞ App」打开 App 列表；2. 找到"网页应用"条目并点击启动 |
| **预期结果** | ① 全屏叠加层中渲染 iframe 组件；② iframe 加载默认页面 `about:blank`（url prop 为空时回退）；③ iframe 带 `sandbox` 属性和 `referrerpolicy="no-referrer"` 属性；④ 页面内容按缩放比例适配窗口尺寸；⑤ 无控制台错误（安全策略违规类错误除外） |
| **关联 FR** | FR-401-007, FR-401-008, FR-401-012 |
| **优先级** | P0 |

### TC-401-005: BasicIframe 加载自定义 URL

| 项目 | 内容 |
|------|------|
| **前置条件** | "网页应用"已添加到 App 列表；目标 URL `https://example.com` 可访问 |
| **步骤** | 1. 通过属性编辑器将"网页应用"的 `url` 属性设为 `https://example.com`；2. 保存配置后启动 App |
| **预期结果** | ① iframe 加载 `https://example.com`（通过 devtools Network 面板或 iframe src 属性确认）；② 缩放适配正常 |
| **关联 FR** | FR-401-007 |
| **优先级** | P1 |

### TC-401-006: 窗口 resize 时 BasicIframe 重新缩放

| 项目 | 内容 |
|------|------|
| **前置条件** | "网页应用"正在运行，iframe 已加载内容 |
| **步骤** | 1. 调整浏览器窗口大小（缩小宽度至 800px 左右）；2. 再次扩大窗口（至 1920px 左右） |
| **预期结果** | ① 每次 resize 后 iframe 缩放比例重新计算，页面内容保持完整可见；② 缩小窗口时 iframe 内容随之缩放缩小；③ 扩大窗口时内容随之放大；④ 连续快速 resize 不产生闪烁或卡顿（calc() 函数 O(1) 复杂度） |
| **关联 FR** | FR-401-009, FR-401-013 |
| **优先级** | P1 |

## 跨应用 & 生命周期

### TC-401-007: 先最小化再恢复 BasicClock

| 项目 | 内容 |
|------|------|
| **前置条件** | BasicClock 正在运行 |
| **步骤** | 1. 点击 BasicClock 标题栏「➖」最小化按钮；2. 观察 3~5 秒后点击底部工具条中"时钟"条目恢复 |
| **预期结果** | ① 最小化时：App 以动画隐藏（opacity: 0, translateY: 60px, pointer-events: none），但 DOM 保持存在；② 恢复时：App 重新可见，时间连续无跳变（定时器在最小化期间持续运行）；③ 底部工具条"时钟"条目运行指示点熄灭（最小化）→ 点亮（恢复） |
| **关联 FR** | FR-401-001, FR-401-005（定时器持续运行 + 关闭时清理） |
| **优先级** | P0 |

### TC-401-008: 两个 App 同时运行并独立操作

| 项目 | 内容 |
|------|------|
| **前置条件** | "时钟"和"网页应用"均已添加到 App 列表 |
| **步骤** | 1. 先启动"时钟" App；2. 再启动"网页应用" App；3. 在"网页应用"可见时最小化"时钟"；4. 关闭"网页应用"；5. 恢复"时钟" |
| **预期结果** | ① 步骤 2：两个 App 同时在叠加层，网页应用覆盖在时钟之上（后启动者 z-order 更高）；② 步骤 3：网页应用仍然可见且完全覆盖底下的时钟（最小化不影响 z-order）；③ 步骤 4：网页应用 DOM 移除，only 时钟在叠加层中（最小化状态）；④ 步骤 5：时钟恢复显示，时间连续无中断；⑤ 工具条运行中 App 列表正确反映每一步状态 |
| **关联 FR** | FR-401-001, FR-401-005, FR-401-014 |
| **优先级** | P0 |

### TC-401-009: 反复打开关闭 App 不产生内存泄漏（定时器/监听器）

| 项目 | 内容 |
|------|------|
| **前置条件** | "时钟"和"网页应用"均在 App 列表中 |
| **步骤** | 1. 启动"时钟" → 等待 2 秒 → 关闭 → 立即再启动（重复 10 次）；2. 启动"网页应用" → 等待 2 秒 → 关闭 → 立即再启动（重复 10 次）；3. 最终关闭所有 App |
| **预期结果** | ① 每次操作均正常（无卡顿、无崩溃）；② Chrome DevTools Performance 或 Memory profiler 中定时器数量稳定（无累积 setInterval）；③ window resize 事件监听器数量稳定（无累积 addEventListener）；④ 最终状态：0 个运行 App，DOM 树中无残留 .BasicClock 或 .BasicIframe 元素 |
| **关联 FR** | FR-401-005, FR-401-014 |
| **优先级** | P1 |

### TC-401-010: 刷新页面后 App 运行状态不保留

| 项目 | 内容 |
|------|------|
| **前置条件** | BasicClock 和 BasicIframe 均在运行状态 |
| **步骤** | 1. 分别启动"时钟"和"网页应用"，确认两者均在叠加层显示；2. 刷新浏览器页面（F5）；3. 页面重新加载后检查桌面状态 |
| **预期结果** | ① 刷新后两个 App 均不自动启动（`desktopApps` 数组在 Desktop.vue 初始化时为空 `ref([])`）；② 叠加层无任何 App 实例渲染；③ App 列表持久化数据仍存在（localStorage `dashboard-desktop-apps`），但运行态 App 实例不保留 |
| **关联 FR** | FR-401-001, FR-401-007（验证 App 运行时状态不持久化） |
| **优先级** | P0 |
